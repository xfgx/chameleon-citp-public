Chaos-Dispersed Transport (CDT) — проверка туннеля
==================================================

ЧТО ЭТО
  cdt-probe — двусторонний тестер туннеля CDT. Растворяет поток в несвязуемые
  фрагменты по хаос-расписанию (порт/размер/тайминг), нода де-диспергирует и
  эширует. Меряет round-trip, потери, throughput. НЕ нужен TUN/админ.

ТОПОЛОГИЯ
  Windows-клиент (за цензурой)  ->  CDT-дисперсия  ->  нода за рубежом (свободный интернет)

ШАГ 0 — КЛЮЧ (один раз, общий для клиента и ноды)
  На любой машине:   cdt-probe -genkey -keyfile cdt.key
  Получится cdt.key (0600). Положи ТОТ ЖЕ файл и на ноду, и на Windows-клиент.
  (Это симметричный хаос-ключ; без одинакового ключа стороны не синхронизируются.)

ШАГ 1 — НОДА ЗА РУБЕЖОМ (Linux-сервер со свободным интернетом)
  Скопируй туда cdt-probe (linux) + cdt.key, затем:
    chmod +x cdt-probe
    ./cdt-probe -node -keyfile cdt.key -c2nbase 20000 -c2ncount 48 -n2cport 23500
  Нода слушает блок UDP-портов 20000-20047 (открой их в файрволе ноды).

ШАГ 2 — WINDOWS-КЛИЕНТ (проверка туннеля)
  Положи cdt-probe-windows-amd64.exe + cdt.key рядом, затем (cmd/PowerShell):
    cdt-probe-windows-amd64.exe -keyfile cdt.key -peer <IP_НОДЫ> -c2nbase 20000 -c2ncount 48 -n2cport 23500 -n 200
  Итог: строка «РЕЗУЛЬТАТ: ... эхо=N потерь=.. RTT ..» и «ТУННЕЛЬ РАБОТАЕТ».
  Эхо>0 = туннель жив. Потери% = потери на NAT/обратном пути. RTT — задержка.

ПРИМЕЧАНИЕ ПО NAT
  Клиент шлёт со стабильного src-порта (23500) — так NAT-дыра совпадает с портом
  прослушивания и ответы ноды доходят. Forward-путь (клиент->нода) диспергирован
  по блоку портов ноды; return-путь (нода->клиент) идёт в NAT-дыру.
