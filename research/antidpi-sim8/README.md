# antidpi-sim8 — игрушечная симуляция пункта 8 (вендорено из astra)

Источник: `/files/astra/sim8.py` + результаты свипа 2026-09-09. Перенесено в
репозиторий, чтобы регрессионная батарея `scripts/antidpi-verify.sh` и CI
`.github/workflows/antidpi-verify.yml` были самодостаточными.

## Честная рамка

Это игрушечная модель (Python stdlib, time-slotted трафик, наивный гауссовский
классификатор, логистическое отображение r=3.99 вместо реального ChaosSync).
Она НЕ измеряет реальный ТСПУ/DPI и НЕ меняет боевой KS. Её назначение —
зафиксировать методологию пункта 8 (конечный совместный поиск политики с
обязательной абляцией ChaosSync→PRF) и детерминированный baseline, от которого
считается регрессия.

## Файлы

| Файл | Назначение |
| --- | --- |
| `sim8.py` | Симуляция, 36 политик, 3 сида, EMB_CADENCE из env (default 5) |
| `baseline/sim8-result-emb{3,4,5,6}.json` | Эталонные результаты свипа 2026-09-09 |
| `baseline/sim8-sweep.log` | Эталонный лог свипа |
| `out-*` | Результаты прогонов antidpi-verify.sh (не коммитить вручную) |

## Ручной запуск

```bash
cd /tmp && mkdir sim8 && cd sim8
for c in 3 4 5 6; do
  EMB_CADENCE=$c python3 /files/VPN/research/antidpi-sim8/sim8.py > run-emb$c.log 2>&1
done
```

Сравнение с baseline делает `scripts/antidpi-verify.sh` (STEP2).

## Эталонные выводы baseline

- Независимая настройка всегда D=1.000 (отдельные короткие M8 — идеальный признак).
- Совместный поиск при ChaosSync: D=0.188 при cadence 3–4 (хрупкий режим,
  embedded M8 + burst), D=1.000 при cadence 5–6.
- PRF-абляция: D=0.190 при cost=0.15 во всех режимах → в этой модели хаотический
  наблюдатель самостоятельного выигрыша не даёт.
