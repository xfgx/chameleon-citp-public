# Threat Model / Модель угроз

> **Предупреждение / Warning:** проект не проходил независимый аудит.
> This project has NOT been independently audited. Не используйте в production.

## 1. Что защищаем / Assets

- **Ключи**: приватный ключ ноды, приватные ключи клиентов, сессионные seed/секреты.
- **Целостность и авторизацию намерений**: нода должна выполнять только авторизованные
  действия (open/resolve) от клиентов из allowlist.
- **Скрытность трафика**: содержимое потоков между клиентом и нодой (ChaCha20-Poly1305).
- **Доступность ноды**: устойчивость к активному зондированию и сканированию.

## 2. От кого / Adversaries

1. **Пассивный наблюдатель** на пути (провайдер, DPI/ТСПУ): видит трафик, не вмешивается.
2. **Активный в-path противник**: может резать, подменять, инжектировать пакеты
   (RST-инъекции, SNI-фильтрация, DNS-перехват).
3. **Активный зондировщик**: сканирует ноду, пытается классифицировать сервис.
4. **Недоверенный клиент** (не из allowlist): пытается использовать ноду как прокси,
   в т.ч. для SSRF против внутренних сетей ноды.

Вне модели: компрометация самой ноды или клиента (физический доступ, rootkit),
глобальный пассивный противник уровня государства с корреляцией трафика,
side-channel атаки на железо.

## 3. Механизмы защиты / Mitigations

| Угроза | Механизм |
|---|---|
| Подделка handshake | mutually-authenticated handshake, allowlist публичных ключей |
| Активное зондирование | 0-байтный blackhole-ответ (45 с), динамический strike-list по IP |
| SSRF через ноду | Anti-SSRF фильтрация (loopback, RFC1918, link-local, CGNAT), декларативный Policy Engine |
| DNS-rebinding | DNS-to-Connection Binding: подписанный `ResolutionObject` (HMAC-SHA256, TTL 300 с) |
| Replay-атаки | MonotonicSeq, ExpiryUnixMs, привязка манифестов к seed новой сессии (CST) |
| DPI-классификация | Opaque wire masking (ChaCha20-Poly1305 + DRBG), CBR+jitter шейпинг, фантомное прикрытие |
| Разрыв при смене сети | Resumable streams / MigrationTicket (HKDF, offsets), CST continuity keys |

## 4. Допущения и ограничения / Assumptions & Limitations

- Криптография собственная, **без стороннего аудита** — возможны ошибки реализации.
- Эффективность обхода DPI зависит от конкретного внедрения цензора и меняется со временем;
  исторические результаты в `docs/` не гарантируют текущую эффективность.
- `refraction-tls` требует кооперативной on-path станции — на обычном VPS это stub.
- Секреты ноды (keyfile, allowlist, токены) должны храниться с правами `0600`;
  запуск сервера рекомендуется под systemd с hardening (см. README и
  `deploy/cham-server.service`).
- Логирование не должно содержать секретов; если нашли утечку в лог — это баг,
  сообщите по процедуре из `SECURITY.md`.

## 5. Планы / Roadmap (безопасность)

- Независимый аудит криптографии и парсеров (когда появятся пользователи).
- Формальная верификация ядра протокола (test vectors в `testdata/`).
- Постоянные fuzz-прогоны парсера кадров и handshake в CI.
