# Пространственный метод научного открытия (Astra 6)

Метод получения новых проверяемых результатов в проекте Chameleon CITP / chaossync / KS.
Ядро: сначала развернуть пространство задачи целиком, затем свернуть его в одно измеримое
утверждение и попытаться его убить замером.

## 0. Входное условие: не начинать без карты

1. Прочитать `VPN/agent.md` — append-only журнал с обязательными правилами для агента.
2. Прочитать `VPN/README.md` §7 «Матрица зрелости» — что зелёное, а что только заявлено.
3. Прочитать доменный документ: `docs/CHAOSSYNC.md`, `docs/CHAOS-METRICS.md`, `docs/KS.md`,
   `protocol/INVARIANTS.md`, `protocol/wire-format.md`.
4. Не повторять работу из раздела «Completed and verified».

СТОП-правило: никогда не читать, не печатать и не публиковать приватные ключи
(`bin/data/*.key`, `/root/build/*.key`), пароли, bearer-токены и деплой-креды.
Структурные выводы обязаны быть ключ-независимыми: мерить на `SelftestMaster`.

## 1. Четыре пространства, которые держать одновременно

| Пространство | Оси | Почему без него не работает |
| --- | --- | --- |
| Слои стека | приложение -> netstack -> intent -> object -> carrier -> провод -> цензор | Ошибка почти всегда на границе слоёв |
| Режимы поля | mu, eps1, eps2, c, T, S, delta, M, rate | Выигрыш на одной оси ломает другую |
| Гипотезы | механизм -> предсказание -> способ убить | Без способа убить это не гипотеза |
| Доказательность | идеальный -> эмулированный -> живой провод -> живой цензор | Смешение уровней = ложное заявление |

Правило пересечений: открытия живут не на осях, а в их пересечениях.
Пример: Э-A обнаружил, что хаос требует eps <= 0.05, а сходимость наблюдателя eps >= 0.35.

## 2. Цикл открытия

1. Развернуть пространство: выписать оси и отметить, что измерено, а что принято на веру.
2. Найти щель: два требования несовместны, либо утверждение живёт без замера.
3. Гипотеза с механизмом: «X даст Y, потому что Z; если Z ложен, увидим W».
4. Сначала измеритель, потом замер. Sanity: eps=0 -> 8/8 положительных, h_KS = 6.32.
5. Попытаться убить: без управления BER ~ 0.5; чужой ключ -> тишина;
   стационарное поле -> тривиальная реконструкция.
6. Честный вывод, включая опровержение. `CHAOS-METRICS.md` опровергает свою же гипотезу
   про h_KS ~ 5 бит/итер — это образец, а не неудача.
7. Дописать в журнал: append-only, с уровнем доказательности, командой, хэшами
   и разделом «не сделано».

## 3. Три уровня доказательности — не смешивать

- L1 идеальный канал: loopback, моки, in-process.
- L2 эмулированный: tc netem, netns+veth, детерминированные потери.
- L3 живой провод: cross-border UDP, RU-нода <-> клиент.
- L4 живой цензор: полевой прогон против ТСПУ провайдера.

Без L4 стойкость к реконструкции не заявляется.

## 4. Гейты, которые нельзя сдвигать

- Э1 carrier golden: 29f2315f353442c2bdd8183ad6d175dcd749929d4b095a6ab4cb6461d2ac5557
- KS golden vector: c043ccf0075a8ec14523f5a8546151a7e0a9e28de406e0f2e7d13438c5fc70ce

Сдвинутый гейт = регрессия, пока не доказано обратное. Fail-closed по умолчанию.

## 5. Признаки настоящей новизны

- Найдена щель между двумя требованиями, а не улучшена одна цифра.
- Есть механизм, а не только корреляция.
- Измеритель провалидирован на известном ответе.
- Проверено, что это не переоткрытие: Short 1994, Perez-Cerdeira 1995, Pecora-Carroll,
  Hayes-Grebogi-Ott 1993, Benettin, теорема Пезина.
- Явно записано, что результат НЕ доказывает.

## 6. Запрещённые приёмы

- Заявлять `go test -race`, TLC, Android-сборку или внешний аудит без записанного прогона.
- Переписывать историю в журнале.
- Отравлять измерители цензора или чужую инфраструктуру. Только своя динамика.
- Новые анти-DPI механизмы до гейтов Priority 0.
- Обвинять внешний мир до исключения своих причин (случай IPv6: три своих бага).
- Обновлять прод без последовательности: SHA-256 -> временный путь -> rollback-копия ->
  рестарт -> проверка службы/слушателя/логов -> откат при сбое.

## 7. Формат выхода

Утверждение / Уровень доказательности / Механизм / Числа с условиями и выборкой /
Контрольная точка / Что это НЕ доказывает / Воспроизведение / Открытые остатки.
