# Протокол честного замера

Перед любым числом, которое попадёт в журнал или вывод.

## Порядок действий

1. Сначала провалидировать измеритель на известном ответе (sanity).
2. Зафиксировать условия: seed, версия, выборка, окно, команда.
3. Прогнать замер, сохранить сырой вывод.
4. Сравнить с нулевой гипотезой и с ожидаемым механизмом.
5. Записать что результат НЕ доказывает.

## Обязательные контрольные точки

| Контроль | Зачем |
| --- | --- |
| eps = 0 sanity | Проверить, что измеритель видит хаос (8/8, h_KS=6.32) |
| чужой ключ | Должна быть тишина, а не частичный сигнал |
| без управления | BER должен быть ~ 0.5 (0.494) |
| стационарное поле | Тривиальная реконструкция — не заслуга |
| квант провода q | sigma_r должна быть < q = 1.53e-05 |

## Методическая честность

- Разделять уровни L1..L4, не выдавать loopback за живой цензор.
- Не округлять шум до нуля: lambda1 в [-3e-06, +4e-06] — это h_KS ~ 0, а не «почти хаос».
- Указывать выборку и окно: NMSE ~ 0 на 500..64000 окнах.
- Отделять корреляцию от механизма.

## Ловушки измерения

- Подгонка seed под красивый результат.
- Сравнение с меняющимся baseline.
- Смешивание единиц (бит/сэмпл vs бит/итер).
- Молчаливое отбрасывание неудачных прогонов.

## Запрещённые и корректные формулировки

| Нельзя | Надо |
| --- | --- |
| «Протокол безопасен» | «L2, гейты зелёные, L4 не проверен» |
| «Неотличим от шума» | «NMSE ~ 0 на X окнах, живой DPI не тестировался» |
| «Proven» | «TLC не запускался, инвариант проверен только юнитом» |

## Чек-лист перед публикацией

- [ ] Sanity пройден.
- [ ] Условия и выборка записаны.
- [ ] Указан уровень L1..L4.
- [ ] Есть раздел «что не доказано».
- [ ] Гейты не сдвинуты без обоснования.
