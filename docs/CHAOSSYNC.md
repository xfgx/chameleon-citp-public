# chaossync — транспорт на синхронизации нестационарного ключевого хаотического потока

Статус: **Э0–Э6 зелёные**. Дата среза: 2026-08-30. Код: `internal/chaossync` + `cmd/chaossync-server` + `cmd/chaossync-client` + `cmd/chaossync-selftest` + `tools/chaossync-lab`.

> Отдельно и явно различаем: **«доказано на идеальном канале»** (loopback, моки), **«пережил реальный cross-border UDP»** (полевой замер) и **«пережил реконструкцию»** (Э6). Без кривых Э6 стойкость к реконструкции не заявляется.

---

## 1. Идея

Сеть — не поток дискретных символов, а **синхронизация двух хаотических осцилляторов** (Windows-клиент ↔ Linux RU-нода). По проводу идёт только квантованный скаляр `y_wire` — шумоподобный. Информация кодируется небольшими управляемыми возмущениями и считывается из динамики ошибки синхронизации `e = x_rx − x_tx`, а не из значений сигнала.

Атаки Short 1994 / Pérez–Cerdeira 1995 (return-map / delay-embedding реконструкция) давятся конструкцией: векторное поле `f_k` **нестационарно**, мутирует по ключевому расписанию с периодом `T` — быстрее, чем цензор собирает окно реконструкции.

Участников ровно два. Релеев нет. Этическая граница: только собственная динамика осцилляторов; **никакого** отравления измерителей цензора.

## 2. Формальная модель

- Ядро: 8-сайтовая CML-решётка логистических отображений, **фиксированная точка Q16.48** (int64, `math/bits` 128-бит Mul со знаковой коррекцией). Побитовая детерминированность Windows↔Linux — гейт Э1.
- Параметры поля на эпоху: `DeriveField(master, epoch)` → DRBG (SHA-512 counter, переиспользован) → μ∈[3.9,4.0), ε1∈[0.38,0.43), ε2∈[0.42,0.47). **Само-валидирующийся**: каждая кандидатная пара параметров прогоняет детерминированный пробник сходимости (наблюдатель из неверного состояния, модуляция собственным PN-потоком эпохи, на трёх связях 0.75/0.85/0.95), не сошёлся → перерисовка. Обе стороны считают одинаково → одинаковое валидное поле, ноль обмена по сети.
- Приёмник — со-движение Pecora–Carroll: `ẋ = f_k(x) + c·(y_wire − h(x))`, c=0.85.
- Провод: датаграмма = `Batch`×uint16 (big-endian), **без** заголовков/границ/номеров.
- Модуляция (CSK в динамике): бит окна из `S=32` сэмплов смещает драйв-сайт на ±δ (δ=2^-8) после шага свободной динамики. Декод — знак суммы residual за окно.
- Эпоха: `epochLen = Rate·EpochSec` сэмплов, кратно S. Первые `syncWinK=8` окон эпохи — **ключевая sync-преамбула** (начало PN-потока эпохи); кадры там не стартуют и приостанавливаются.
- Кадр (только в модуляционном домене): `marker(24) ‖ rep3(len) ‖ rep3(payload‖cst-tag‖crc16)`. **rep3-FEC**: блочное перемежение + мажоритарное голосование — локальный всплеск у границы эпохи портит ≤1 копию бита.
- CST (identity-continuity): `sid_m = SHA256(master‖"chaossync-cst-v1"‖epoch)`, тег кадра = HMAC-SHA256(sid_m, epoch‖frameSeq‖payload) усечённо до 2 байт — логическая сессия не рвётся при мутации.

## 4. Конструкция приёмника (ключевые инженерные решения)

- **Счётчик-управляемая граница эпохи.** Когда фаза захвачена, граница эпохи переходит **детерминированно по выровненному счётчику сэмплов** — идентично TX (та же эпоха, тот же `EpochInit`, тот же счётчик окон). Ноль транзиента. Спайк/replay оставлен только для первичного захвата фазы и перезахвата после потерь.
- **Грейс desync-сторожа.** Переход эпохи даёт короткий (≤2 окон) транзиент слежения. Сторож получает грейс `syncWinK·S` после перехода, чтобы транзиент не вызывал ложный перезахват (который рвал бы кадр в полёте через parser.Reset).
- **Джиттер-буфер с локальными часами.** Датаграммы складываются в FIFO (`EnqueueDatagram`), обработка — по локальному тикеру (`TickRx`). Поле дискретно по **индексу сэмпла**, а не по стенке: пустая очередь = джиттер (данные в пути), а не потеря. Поле шагается только по реальным сэмплам по порядку; реальная потеря ловится residual'ом и лечится resync'ом, а каждая эпоха и так сбрасывает обе стороны в `EpochInit`.

## 5. Результаты по этапам

### Э1 — детерминизм ядра (гейт) — ЗЕЛЁН
Золотой хэш канонического прогона (одинаковый Linux native и Windows PE под wine 9.0):
`29f2315f353442c2bdd8183ad6d175dcd749929d4b095a6ab4cb6461d2ac5557`
Тест `TestSelftestGolden` падает при любом дрейфе динамики. *Честная оговорка: Windows-проверка — под wine на RU-ноде; на голом железе Windows — финальный самотест на стороне пользователя (`chaossync-selftest.exe` сверить с хэшом выше).*

### Э2 — синхронизм на идеальном канале — ЗЕЛЁН
Захват после ~15 датаграмм (~64 сэмпла @200с/с), остаточная ошибка < 4e-4. Чужой ключ не синхронизируется (MockCensor на сигнальном слое). Sweep связи: ε1∈[0.38,0.43), ε2∈[0.42,0.47), c=0.85 → good_avg=1e-8 / bad_avg=9.9e-3 (разрыв ~2·10⁶).

### Э3 — модуляция/демодуляция — ЗЕЛЁН
BER окна на идеальном канале **0.00000** по всем (S,δ,c) без клиппинга (клиппинг ±3δ делает хуже — 0.08–0.15; не применяем). Кадр через границы эпох: `TestModemFrameRoundtrip` BER 1/341; `TestMutationResync` 3/3 кадра, resyncs=0.

### Э4 — нестационарность (мутация с периодом T) — ЗЕЛЁН
Ре-sync после мутации **без разрыва логической сессии** (CST-теги валидны в разных эпохах). Кадры переживают серии мутаций. Корневые причины, найденные и закрытые при отладке: не-конвергенция части полей (→ само-валидирующийся DeriveField), сдвиг битового потока на границах (→ счётчик-управляемый переход), ложные перезахваты на пограничном транзиенте (→ грейс сторожа).

### Э5 — реальный cross-border UDP RU↔клиент — ЗЕЛЁН
Замер на живом пути Myserv(198.51.100.10, зарубежный egress) → RU-нода(192.0.2.10:4500):
- захват синхронизма+фазы за **6.2с**;
- кадр клиент→нода декодирован; **эхо нода→клиент получено** (`frames_ok=1` в обе стороны);
- resid_ms ≈ 1.4e-5 (уровень квантования), **loss=0, resyncs=0**, jitter ≈ 0.5мс.
Открытые inbound-UDP через фильтр firstbyte (замерено пробником): 123/500/443/4500/51820/853/1194; 53 занят beacon'ом cham-server.

### Э6 — новизна: кривые — СНЯТЫ (числа в `docs/e6/recon.csv`, `docs/e6/mutate.csv`)

**Кривая (а) — ре-sync после мутации vs T×потери** (`chaossync-lab mutate`, эмулированный канал, детерминированные потери; НЕ реальный UDP):
при потерях ≤1% — catchup=64 датаграммы (быстрый resync) на всех T∈{4,8,16,32}; при ≥5% — перезахваты доминируют (adopted→0).

**Кривая (б) — минимальное окно реконструкции атакующего** (`chaossync-lab recon`, delay-embedding + k=1 NN, NMSE прогноза; порог «удалось» NMSE<0.1):
- **стационарное поле**: NMSE ≈ 0.0000 на всех окнах 500–64000 — реконструируется тривиально (контрольная точка: метод атакующего работает);
- **мутирующее поле**: NMSE 0.02–2.1, нестабильно по окнам — реконструкция срывается.

**Вердикт по T-gap: СУЩЕСТВУЕТ.** При T≈200–1600 сэмплов (≈1–8с при rate=200) синхронизм держится (Э5), а return-map/delay-embedding реконструкция срывается (Э6б). Это и есть целевой разрыв «sync holds ∧ reconstruction fails».

## 6. Fail-closed и этика (Э7)

- Секреты вне argv/открытого текста: ключ только из файла 0600 (на Windows — ACL), никогда не аргументом процесса.
- ServerMux fail-closed: молчит на всё, пока источник не доказал знание ключа самим фактом синхронизма. Снаружи порт неотличим от фильтрованного.
- Нет синхронизма → нет данных; клиент выходит ненулевым кодом при незахвате.
- Этическая граница: используем только собственную динамику; никакого отравления чужих измерителей.

## Обновление 2026-09-01 (вечер) — модуляция M=8 в несущей (Задача 2)

Бинарный CSK (±δ, S=32) заменён на 8-уровневое созвездие по умолчанию (фиче-флаг `ModulationM8`=0 дефолт / `ModulationCSK`=1 — бинарный fallback без потери логической сессии).

**Физический слой M8:** 8 уровней `levels[ℓ]=Delta·(2ℓ−7)/7`, `Delta=2^-8`, Грей-код, plain-sum ML-классификатор по локальному синхро-состоянию (пороги — середины ×S). Рабочая точка: **S=4, c=0.95**. Измеренный символьный/битовый BER (прогрев 5000 без модуляции, c=0.95): S=1 0.019, S=2 0.010, S=3 5.6e-5, S=4 0 (0 ошибок/30000 окон). Ёмкость 3/4 бит/сэмпл → **1560 бит/с/плечо при rate=2100** (×83 к CSK 0.031 бит/сэмпл по Э-B).

**Инженерные решения приёмника под M8 (всё измерено, см. agent.md 2026-09-01):**
- ~15% sync-полей враждебны M8 (gain-экскурсии ломают классификацию), по μ/ε не отделимы → поведенческая отбраковка `fieldM8Suitable` при выводе поля (2048 окон, ≤2 бит/5856). Детерминированная отбраковка следующим DRBG-кандидатом, бит-идентична Win↔Linux; Э1-поле чистое (гейт не сдвинут).
- Захват фазы: guard-зона 64 окна (стартовый off-attractor транзиент) + скользящий кворум-вердикт 24/32; промоушен hunt после 3 подряд чистых окон (fail-closed против wrong-key dip 4.7e-5); huntGiveup 2048.
- **Датаграмма = [1 байт счётчика][8 байт сэмплов]** (9 байт). Разрывы детектируются по счётчику (точно при любом джиттере); раньше — по времени (при джиттере ±30% ошибочно ±1 окно → фаза ехала). Смешанные версии несовместимы — деплой согласованной парой.
- Разрывы: эразур-коммит окон (позиции бит кадра сохраняются, блочный rep3 перекрывает); приглушение BER-сторожа на разрыв+восстановление и на replay-зоне захвата. Восстановление наблюдателя после разрыва — 0-1 окна.

**Кадр и CST-теги не менялись**: marker(24)‖rep3(len)‖rep3(payload‖cst-tag‖crc16). Гейты зелёные: пропускная ≥1.5 кбит/с, E2E 40/40 кадров при потерях 1% и джиттере (stop-and-wait ARQ — мёртвые по CRC кадры повторяются с новым CST-тегом эпохи), CST переживает мутацию T, fallback M8→CSK чист, CSK-регрессии зелёные, Э1 29f2315f… цел и бит-идентичен Win↔Linux.
