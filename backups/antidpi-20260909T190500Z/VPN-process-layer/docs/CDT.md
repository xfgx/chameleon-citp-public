# CDT — Chaos-Dispersed Transport (растворение потока, не маскировка)

> **Статус 2026-09-01: CDT СНЯТ с роли data-plane** — заменён keystream-инверсией ядра chaossync (см. `docs/KS.md`, драйвер `cmd/ks-vpn`, юнит `ks-vpn-node`). Документ и код оставлены как лабораторная справка; CST и ротация эпох переиспользованы в KS.

Статус: **ядро + data-plane реализованы и доказаны на реальном cross-border пути**. Код: `internal/chaossync/cdt.go` (ядро), `cmd/cdt-server`, `cmd/cdt-client` (data-plane). Дата среза: 2026-08-31.

> Принципиально не мимикрия. Мимикрия говорит «выгляди как X». CDT говорит: «не будь ничем единым — рассыпься на неклассифицируемые, несвязуемые фрагменты, чей узор — хаос-секрет».

## 1. Идея

Философия spread-spectrum / DSSS из радио (сигнал ниже шумового порога, восстановим только с кодом), честно адаптированная под ограничение «только клиент + нода, без третьих сторон».

**Что несёт объём:** обычный быстрый потоковый шифр (AES-256-GCM data-plane). Хаос объём НЕ несёт — физика синхронизации (Э1–Э5) даёт низкую скорость, мы это измерили и не врём себе.

**Что делает хаос:** вся наблюдаемая геометрия потока диктуется общим хаос-keystream (тем же синхронизированным ключевым материалом, что доказывает chaos control-plane):
- на какой порт блока ноды уходит каждый фрагмент;
- размер каждого фрагмента;
- межпакетный интервал;
- время жизни каждого микро-потока (churn src-порта).

## 2. Результат для наблюдателя

1. **Неклассифицируемость** — нет протокольной сигнатуры; размеры/тайминги шумоподобны (max-entropy shaping, не имитация).
2. **Несвязуемость (ядро новизны)** — наблюдатель не может сгруппировать пакеты в один поток: нет стабильного во времени 5-tuple. Один физический туннель выглядит как облако несвязуемых короткоживущих высокоэнтропийных обменов. Жирная труба не собирается без знания хаос-состояния.

Восстановить туннель = решить задачу группировки фрагментов, ключ к которой — нестационарный хаос, не поддающийся реконструкции по построению (Э6).

## 3. Архитектура

- `GeometrySource` — детерминированный генератор геометрии из хаос-ключа (DRBG поверх epochSeed). Обе стороны выводят идентично, побитовый детерминизм Windows↔Linux сохранён. Геометрия мутирует вместе с эпохой хаоса (T).
- `Fragmenter` (клиент) — режет поток на хаос-размеры, запечатывает AEAD (seq внутри, случайный nonce снаружи — сам не связываем), шлёт на хаос-порт с хаос-интервалом, churn src-порта по TTL микро-потока.
- `Defragmenter` (нода) — знает узор (та же GeometrySource): опознаёт фрагменты по nonce из расписания + AEAD-тегу, де-диспергирует по скрытому seq, переупорядочивает, fail-closed молчит на шум.

## 4. Переиспользование (из сборки chaossync)

| Подузел | Роль в CDT |
|---|---|
| Хаос-ядро Э1–Э4 | генерирует keystream геометрии (порт/размер/тайминг/TTL), не control-сигнал |
| Синхронизация Э5 | обе стороны знают, куда/когда уйдёт следующий фрагмент; де-диспергирование тривиально |
| Автопилот | выбирает степень дисперсии (сколько портов, насколько рвать тайминг) как trade-off «невидимость vs накладные/латентность» — хук есть (GeomConfig), авто-подбор — следующий шаг |
| DPI-профайлер | замер, какая геометрия не триггерит ТСПУ на текущем маршруте — следующий шаг |
| CST | логическая идентичность туннеля поверх эфемерных фрагментов — следующий шаг (сейчас seq внутри AEAD даёт непрерывность в эпохе) |
| Каскад RU→Myserv, fail-closed, этическая граница | без изменений |

## 5. Доказанные числа

Ядро (in-process, идеальный канал):
- детерминизм геометрии: обе стороны идентичны на 5000 фрагментов; мутация эпохи меняет узор;
- round-trip: 100 КБ → 151 фрагмент → собрано без потерь;
- несвязуемость: 96.6% уникальных 5-tuple, макс. серия одного tuple = 2, энтропия портов 94% от максимума.

Data-plane (реальный провод):
- loopback (нода RU): 5 МБ за 6.23с = 7.03 Мбит/с, 94.6% уникальных tuple, сборка 100%;
- **cross-border Myserv→RU через интернет**: 3 МБ за 4.76с = **5.52 Мбит/с**, 96.2% уникальных (dstport,size), энтропия интервалов 8.18 бит, нода приняла **3921/3921, потерь 0**.

## 6. Честная матрица (что даёт / НЕ даёт)

| Свойство | CDT даёт? | Уверенность |
|---|---|---|
| Полная скорость серфинга/видео (Мбит/с) | **Да** — объём несёт обычный шифр | Высокая (5.5 Мбит/с замерено cross-border) |
| Неклассифицируемость содержимого/протокола | Да — max-entropy, не мимикрия | Высокая (замерено) |
| Несвязуемость (нет единого жирного потока для per-flow DPI/ML) | Да — ядро новизны | Средне-высокая (замер in-process; нужен полевой DPI-замер) |
| Устойчивость к active probing одного фрагмента | Да (фрагмент короткоживущий, не отвечает как протокол) | Средняя |
| Скрытие суммарного объёма между клиентом и AS ноды | **НЕТ** — теорема сохранения объёма | Высокая (честно не даёт) |

## 7. Честный предел

CDT побеждает механизмы, которыми ТСПУ реально фильтрует на потоке: per-flow классификацию, протокольные сигнатуры, flow-linking, ML по признакам потока. Их он ломает, потому что потока как объекта нет — есть облако несвязуемых фрагментов.

Чего CDT НЕ побеждает: глобальный объёмный учёт («этот клиент льёт много байт в сторону этой AS за час»). Но такой анализ ТСПУ в реальном времени по-пользовательски массово не делает (дорого + ложные срабатывания на легитимных тяжёлых пользователях). CDT бьёт по реальному противнику, не по гипотетическому всеведущему.

## 8. Статус полной формы (обновлено 2026-09-01)

Сделано и закрыто тестами на RU-ноде (`go test ./internal/chaossync` — зелёный):

- **Непрерывный туннель через ротацию эпох** — ротационные Fragmenter/Defragmenter, epochSink cur/prev со straddle на границе, глобальный seq непрерывен сквозь ротации (TestCDTRotationMultiEpoch). Живой инстанс под systemd: `cdt-socks-node.service` на RU-ноде.
- **CST-идентичность туннеля** — `cdt_cst.go`: AAD фрагмента = sid эпохи направления (KDF от master, `cdt-cst-v1`; на провод не уходит, формат `nonce‖ct` неизменен), `TunnelID` для журналов обеих сторон. Replay/cross-epoch правила покрыты `TestCDTCst*`: straggler границы принимается в окне straddle, повтор и забытая эпоха — отбрасываются.
- **Автопилот дисперсии** — `RiskFromMetrics` + `ClassStepper` (гистерезис ±1, dwell 2 эпохи) + in-band REQ/ACK переключение класса на границе эпохи с lockstep обеих сторон (`cdtstream`; потерянный REQ переоформляется с новым fromEpoch — `TestStreamGeomAuto*`). Флаг `-geomauto` в cdt-socks (конверт приёма до 512 портов); точка подачи полевого риска — `Stream.SetExtRisk`.
- **TUN↔CDT мост** — доказан ранее (§9); `cmd/cdt-vpn` досинхронизирован в каноническое дерево и собран на RU-ноде.

Осталось (инфраструктура и поле — за владельцем):

- Мульти-IP дисперсия (нода с блоком адресов, не только портов) — опция развёртывания.
- Полевой DPI-замер несвязуемости против реального ТСПУ (сеть владельца) → подача в `SetExtRisk`.
- Wintun-порт TUN-моста (`tun_windows.go`) + живой Windows-прогон.

## 9. TUN↔CDT мост — реальный IP-трафик (доказано end-to-end)

`cmd/cdt-tun` — симметричный двусторонний мост: IP-пакеты из TUN → растворение в
фрагменты по хаос-геометрии → peer; сборка обратно → TUN. Направления разделены
(GeomConfig.Dir) — нет повтора nonce. Ключевые доказанные результаты:

- **IP-over-CDT**: ping через туннель (netns+veth на ноде) — 4/4, 0% loss.
- **Реальный интернет через туннель**: клиент пингует 8.8.8.8 — пакет идёт
  клиент-TUN → CDT-дисперсия → нода-TUN → NAT → интернет → обратно. 4/4, 0% loss.
- **Видео-грейд throughput**: реальный TCP поверх IP-over-CDT — **3.71 Мбит/с**
  (скачивание 20 МБ). 480p ~1–2, 720p ~3–5 Мбит/с → в диапазоне.
- **Устойчивость к потерям**: gap-skip (reorderWindow) — **10% потерь фрагментов
  туннель живёт** (потерянный фрагмент = потерянный IP-пакет, верхние слои перешлют).
- **Самодостаточный TUN**: настройка интерфейса чистым ioctl + /proc, БЕЗ iproute2
  (нет `ip`/`sysctl`) — работает в минимальных контейнерах и ложится в основу Windows.
- **packet-aligned фрагменты**: 1 IP-пакет = 1 фрагмент (иначе дефрагментер отдавал
  куски пакета и TUN отбрасывал обрезки — TCP над туннелем не работал).
- **NAT-traversal**: fixsrc (стабильный src-порт клиента) + нода учит адрес клиента
  динамически по валидным фрагментам (не по шуму сканеров).
- **Windows-портируемость**: ядро CDT (geometry/defrag/AEAD) кросс-компилируется
  GOOS=windows без изменений (cdt-client.exe, cdt-server.exe собраны).

### Найденные и починенные баги (честно)
- data race на ServerMux.peers (crash ноды под фоновым шумом интернета) + кэш DeriveField.
- двусторонняя дисперсия без разделения keystream → повтор nonce (чинится Dir).
- IPv6 router-solicitation на старте → дыра в seq → ступор дефрагментера (gap-skip + подавление).
- резка IP-пакетов на части → TUN отбрасывал обрезки (чинится packet-aligned).

### Честные пределы среды (не CDT)
- Кросс-border full-TUN демо заблокировано: тест-контейнер без CAP_NET_ADMIN (не создать TUN).
  Компоненты доказаны раздельно: cross-border data-plane (5.52 Мбит/с) + TUN-мост на ноде.
- Windows-клиент с Wintun: ядро готово и портируемо; нужен реальный Windows-хост для теста
  (Wintun требует admin + адаптер).
- DPI-профайлер: полевой замер, какая геометрия не триггерит ТСПУ (подключить к ручке риска).
- Мульти-IP дисперсия: нода с блоком адресов (опция развёртывания, сейчас блок портов).
